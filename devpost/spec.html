CyberShield AI

A local-first Django assessment that calculates risk with transparent rules, then asks OpenAI only to explain the actions the app has already chosen.

How this works

Think of Django as the app’s workshop: it receives the owner’s answers, applies the published scoring rules, and decides which action cards belong on the plan. The browser handles the question flow and display. OpenAI is a writing helper called only after Django has chosen the findings and actions.

Rules decide; AI explains. If OpenAI is unavailable or not configured, the score, risks, priorities, and predefined next steps still work.

Answers stay in browser memory for this visit and are not saved to a database. A refresh starts a new assessment. The OpenAI key stays in Django’s server environment and never goes to the browser.

System flow

The guidance request recalculates the canonical findings on the server. The browser cannot set the score, priority, ranking, or action mapping.

Deterministic

Score & rank

Equal area weights, explicit uncertainty, high/moderate impact, and the approved fixed tie-break order.

Constrained AI

Explain & personalize

OpenAI can fill explanation and first-step text for server-selected action IDs only.

Always available

Fallback plan

Predefined actions preserve a useful result if the AI key, balance, network, or response is unavailable.

Transparent scoring and priorities

Self-reported score

Equal weights

Yes = 12.5 points · Not sure = 6.25 · No = 0. Sum all eight areas for 0–100. This is not a technical measurement.

80–100

Strong

Most important controls appear to be in place, based on the answers provided.

50–79

Needs Attention

Meaningful gaps should be addressed.

0–49

High Risk

Several important controls appear to be missing or need urgent attention.

Finding priority is separate from score: No + high impact = high confirmed gap; No + moderate impact = medium confirmed gap. Not sure gets the same impact-based priority but is labeled for verification. Yes creates no finding.

High impact: backups, passwords, MFA, and user access. Moderate impact: updates, Wi-Fi/network, device protection, and employee practices.

Deterministic tie-break: higher priority first, confirmed No before Not sure at the same priority, then the fixed eight-area order from the PRD. The same answers always produce the same ordered findings.

AI cannot change assessment results. Python rules alone calculate the exact score (Yes 12.5, Not sure 6.25, No 0), severity, priority, order, and risk-to-action mapping. AI may explain only the actions Django selected; it cannot calculate scores, change severity, reorder priorities, or invent risks.

One assessment journey

1 · Assess

Landing page → eight guided questions. JavaScript keeps answers and handles Back/Next, progress, and unanswered-field feedback.

PRD: Landing, Assessment, Guided Assessment · Files: index.html, app.js, app.css

2 · Calculate

Analyze My Security posts the eight choices to Django. Python validates answers, sums the score, creates findings, applies tie-breaks, and selects linked actions.

PRD: Transparent Score and Risk Priorities · Files: views.py, catalog.py, rules.py

3 · Understand

The dashboard displays the self-reported score, status, all eight area states, prominent top risks, and the “not a technical measurement” note.

PRD: Results Dashboard · Files: app.js, index.html, app.css

4 · Get guidance

Clicking Get AI Guidance makes Django recompute and freeze risk/action IDs before it calls the configured adapter.

PRD: AI Guidance and Action Plan · Files: guidance/service.py, guidance/openai_adapter.py

5 · Act

AI selects only approved wording styles; Django renders action-card text from fixed, risk-linked copy. Preventive cards are labeled; no missing risk is invented.

PRD: Results and Action Plan, AI Guidance and Fallback · Files: catalog.py, app.js

Data, trust, and boundaries

During the visit

Answers, analysis, and guidance remain in browser memory. Refresh/close clears them. Django does not save assessments.

On the server

Django validates every request and recomputes the score, ordered findings, and selected actions. It ignores client-computed results.

Sent to OpenAI

Only categorical answers, rule-generated result context, and selected action descriptions. No business identity or free-text secrets are collected.

Key and response retention

The key is read by Django from local .env. The OpenAI request sets store=false; abuse-monitoring retention can still apply for up to 30 days.

Product boundary: self-reported controls only. No scanning, verification, accounts, saved assessment history, or invented risks.
Approved POC boundary: Django templates and vanilla JavaScript; answers/results held temporarily in browser memory only. No authentication, database, Supabase, or React unless a concrete approved PRD requirement makes one necessary. The provider-neutral Django guidance service owns the contract; OpenAI is replaceable and its API key stays in a server environment variable.

Local setup and demo

Windows PowerShell from the project folder:

py -3.14 -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python manage.py runserver

Use the installed Python 3.14.8 runtime with Django 5.2.8 or later in the 5.2 LTS series; Django 5.2.8 added Python 3.14 support. Open http://127.0.0.1:8000. Add a key only to the ignored .env file if you decide to enable live guidance. With no key, use the real rules-based fallback. No database migration or hosted service is required.

API credits and cost

Current low-cost model for the spec: GPT-6 Luna is listed for $0.10 per million input tokens and $0.50 per million output tokens. Its API free tier is not supported, though your account may have promotional API credits. The app makes one bounded request only after the owner clicks for guidance.

Check before paying: open the OpenAI API billing overview for the correct organization and inspect the available credit balance. Free API credits, if present, are used before purchased credits. ChatGPT billing does not include API usage. If no credits are available, the current minimum initial prepaid purchase is $5; the app can remain in fallback mode without buying anything.

Before a live demo: use a dedicated API project and set a project hard spend limit and alert. The hard cap may be enforced with a small delay, so check usage as well. Keep the API key in the server environment and never expose it in browser code or a public repository.

Pricing, credits, model access, and billing screens can change. The account balance is not visible to this workspace and remains for you to check privately.

Approved decisions and remaining pre-spend check

The approved architecture preserves the eight constraints: deterministic Python scoring and documented tie-breaks; AI limited to explanations for server-selected results; full rules-based fallback; server-only API key; provider-neutral guidance interface; approved Django templates plus vanilla JavaScript; no unnecessary auth/database/Supabase/React; and no permanent storage of assessment answers or business data. Python 3.14.8 is the selected runtime; Django 5.2.8 or later in the 5.2 LTS series supports it.

GPT-6 Luna is the initial low-cost model setting in the spec. Before enabling a paid API call, check the account-specific API credit balance and current model pricing. The balance is not visible to this workspace. Local build and fallback-mode demo do not require a key or purchase.
