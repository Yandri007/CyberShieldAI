CyberShield AI

A local assessment that turns a small-business owner’s answers into a transparent score, ordered findings, and practical risk-linked actions. Django owns the rules and all displayed guidance; AI can select only approved wording styles.

Source code snapshot: commit 2294d67. This map is a reference to that code and may drift after later edits.

One answer through the app

Three-stop code route

Use the approved Backups = No example. Follow its fixed action ID from the question catalog to the card shown in the browser.

Define the answer and impact

assessment/catalog.py · AREAS

Find the Backups entry. It records the question, high-impact classification, and remediation/verification action IDs.

Calculate the finding

assessment/rules.py · _finding_for(), calculate_assessment()

A No contributes zero points for that area and creates a confirmed finding. Django sorts findings with the documented priority and tie-break rules.

Select and display the action

assessment/guidance/actions.py · select_actions()
static/assessment/js/app.js · renderAction()

The finding selects backups-recovery; the browser renders its What, Why, and How fields using text nodes.

At the request boundary, assessment/views.py · guidance() recomputes the result from the eight answers. assessment/guidance/service.py validates optional style IDs and otherwise returns the same rules-based plan.

To change this, start here

Question text, area order, impact: assessment/catalog.py, AREAS.
Points, finding certainty, priority order: assessment/catalog.py and assessment/rules.py.
Risk-linked and preventive action wording: assessment/guidance/actions.py, ACTION_CATALOG and PREVENTIVE_ACTIONS.
Dashboard/action-plan presentation: static/assessment/js/app.js and static/assessment/css/app.css.
AI output boundary and fixed wording: assessment/guidance/openai_adapter.py and assessment/guidance/service.py.

A practice to reuse

Make a product rule observable before adding AI. The PRD fixes the point values and impact-based priority rules; calculate_assessment() implements them deterministically, and fake-adapter checks show invalid model output falls back without changing results. On another project, define a few sample inputs and expected outcomes before connecting a generative service.
Run locally: in PowerShell, from the project folder run py -3.14 -m venv .venv, then .\.venv\Scripts\python.exe -m pip install -r requirements.txt and .\.venv\Scripts\python.exe manage.py runserver. Open http://127.0.0.1:8000/. No database or API key is required for the rules-based flow. See README.md for setup details.
